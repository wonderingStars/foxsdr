## Rules every component keeps

1. **Only `Theme` tokens.** No colour literal, no typeface name, no size that `Theme` already has (`Theme.key-h`, `Theme.chip-h`, ...). `tests/test_slint_house_rules.cpp` fails the build of the library otherwise. Sizes the theme has no metric for (a 92×64 STOP dome, a 180 px ramp) are literal lengths in the component, taken from the artboard.
2. **Nothing drawn from nowhere**: import `Theme` from `"theme.slint"` in every file.
3. **Every interactive component** has `in property <bool> enabled: true;`, `in property <string> tooltip;` shown through `TipTimer` (it writes the global `TipState`; the window's last element `TipLayer` draws the tip, so the click that follows a tip is not swallowed as a `PopupWindow` tip swallowed it; only a component that lives INSIDE a `PopupWindow` uses `PopupTipTimer`), `accessible-role` and `accessible-label` (default: its label), and never acts while disabled. Disabled look (the kit's `.btn[disabled]`): `Theme.key-disabled-bg` ground, `Theme.key-disabled-fg` text, border at half alpha (Slint has no dashed border).
4. **Labelled keys keep ~40 % spare width** over their English string (34 languages): `min-width` from the theme and the artboard's padding, never a width that hugs the text.
5. **No emoji.** Glyphs are the SVG icons under `ui/icons/` (`Image { source: @image-url("icons/close.svg"); colorize: Theme.fg-soft; }`) or plain text; the digit nudge arrows are the text "▲" / "▼" as on the sheet.
6. **Callbacks** are verbs in the past tense or the event: `clicked`, `changed(float)`, `nudge(int)`, `selected(int)`, `toggled(bool)`, `menu-requested(length, length)` (pointer position in the component), `right-clicked(length, length)`.
7. **Structs and enums** a test or the host needs are `export`ed and re-exported from the specimen file (`export { Theme, Skin, Workbench, ChipTone } from "../chips.slint";` style), or the generated C++ cannot name them.
8. **Model-driven lists** take `[T]` properties and draw with `for`; nothing is drawn from a fixed count.
9. Lengths that come from a measurement in Hz or dB arrive as **fractions 0..1** (`float`) of the component's width or height: Slint floats are 32-bit, a frequency in Hz does not survive them (the host does the arithmetic).
10. **Every word a user reads goes through `@tr`.** `@tr("English text")`, or `@tr("... {} ...", value)` for a sentence with a value in it (never a concatenation of translated pieces); the msgid is the English text itself, with no translation context, so where the ImGui window says the same thing use ITS wording and the catalogue entry applies for free (`resources/lang/<code>.json` keys are the English). What stays bare is a host id or kind, a unit or radio vocabulary (Hz, dB, mode and protocol names, I/Q), a typeface name, or sample data the host replaces, and each such line carries a trailing `// not-translated: <reason>`. `tests/test_slint_house_rules.cpp` rule 5 refuses any other string literal with two consecutive letters (specimens apart: they are test sheets, never shipped).
11. **A row holds its width.** A layout asks its parents for its minimum width and every parent without a width of its own passes the ask up to the window, which lays the body out wider than itself and cuts the right-hand side off (seen with the French catalogue: the receiver strip, the tab row and the status bar). So each row of the main window keeps its layout behind a `Rectangle { width: parent.width; height: parent.height; clip: true; }`, a measuring layout (`StateChips`' natural width) sits behind a `Rectangle` of its own width, a `Caption` elides (`min-width: 0px`) instead of widening its block, and a component a layout sizes declares its `preferred-width` (`Checkbox`). `tests/test_slint_constraints.cpp` records which wrappers hold the line; the main screen is checked at 1100 px.

## Specimens and tests

- `ui/specimens/<family>_specimen.slint` exports `component <Family>Specimen inherits Window` with an explicit `width`/`height` and `background: Theme.bg;`, a `TipLayer { x: 0px; y: 0px; win-w: root.width; win-h: root.height; }` as its LAST element, every variant at an **absolute** `x`/`y` (no layout at the top level), none overlapping, and a table in the file's header comment: `x, y, w, h — what`. Interactive state the test must observe is surfaced on the specimen root (`in-out property <int> clicks;`, `in-out property <bool> latched;`, `callback fired(string);`).
- `tests/test_slint_<family>.cpp` uses the harness (`render_harness.hpp`): `installHeadlessPlatform()`, `auto ui = <Family>Specimen::create();`, `Frame f = render(ui, W, H);`, probes with `f.near / rowNear / colNear / countNear / countInk / firstRowNear`, interactions with `click / press / release / moveTo / scroll / keyTap / ctrlTap`, `settle(ms)` for timers, `f.savePng(shotDir() + "<family>-specimen.png")`, `CHECK(...)` from `test_check.hpp`, `return testSummary("test_slint_<family>");`. At least one geometry check (height, width, border position) and one colour check per variant, and one interaction check per callback. The typefaces are the embedded Inter and JetBrains Mono (third_party/fonts): assert **ink in a region** (`countInk`) and sizes from the artboard, never pixel positions computed from a glyph width.

Measurements are the Workbench sheets' CSS. `cap` = 10 px / 600 / 0.8 px letter-spacing, muted. Heights and fonts come from `Theme.*` metrics of the same name.

**The key capture.** A press on a cap calls `keys-capture(id)`; the host sets that row's `capturing` (in place or by publishing a new model) and the cap takes the keyboard, says "Press a key..." in the warn tone with the focus ring, and turns the next key into the chord text the config stores - modifiers in the order Ctrl, Shift, Alt, then the key's name from `src/gui/key_bindings.cpp` (`Plus` for the Equal key, `PageUp`, `F5`, `Space`, `A`..`Z`; the table is in `KeyCap.key-name`) - calling `keys-captured(id, chord)`. Esc is `keys-cancel()`, Backspace is `keys-clear(id)`, a second press on the listening cap is `keys-cancel()`; a modifier alone is ignored. The keyboard going elsewhere ends the listening 80 ms later (not at once: the host moves the listening in more than one step). Slint 1.18 on Windows delivers Ctrl+Alt+key with neither modifier set (the AltGr rule), so a Ctrl+Alt chord cannot be captured.
