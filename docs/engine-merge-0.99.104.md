## 4. The engine side, where it lives now

`Engine::closeAudioMinute` takes master's two discounts. A minute in which `pluginScans_` moved (a rescan began) steps nothing - not for the receiver's sink, not for any patch speaker - counts nothing toward the quiet run and says why (`audio: buffer kept at N ms - the starved
callbacks came in a minute that reloaded plugins`, only when something starved); the mark is consumed at the end of `Engine::initialise`'s first scan so the session's first minute is judged. A minute's starved callbacks lose one per user stop (`receiverStops_`, counted
by `Engine::stopReceiver` only for a stop that stopped something) before a raise is judged, and a raise the discount prevented says so (`audio: buffer kept at N ms - S of the T starved callbacks came with receiver stops`); the quiet run is untouched.
`Engine::closeDspMinute` takes the marks (`takeRingHighWaterSamples`, `takeDspBlockLongestNs`) every minute whether or not anything was lost, keeps the session's maxima, writes the second line (`dsp: ring high water 100% of 1048576 samples, 14 writes cut, longest DSP block 3 ms`)
and files the `ringdrop` issue report only when `ringDropWorthAReport(dropped, read)` (0.05% of what the minute read). `Engine::pollDspMinute` publishes the counters and the ring figures every pass (`publishRingFigures`: `Pipeline::ringCapacity()`, which takes the control mutex
like the `activeSource()` the pass already reads, and four relaxed loads). New members in engine.hpp: `audioRescansAtLogStart_`, `receiverStops_`, `audioStopsAtLogStart_`, `dspCutAtMinute_`, `dspRingHighWaterSession_`, `dspBlockLongestNsSession_`.
