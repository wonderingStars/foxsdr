# FoxSDR 0.99.74 development notes

**POCSAG opens its settings and received messages together, and configures the receiver automatically in this development build.** With POCSAG 1.0.3 fitted, opening or starting the plugin selects NFM, its declared bandwidth and flat audio while keeping a manually tuned paging frequency. The plugin defaults to text, offers numeric and function-code modes on its own settings page, and detects baud rate and polarity automatically. Its UK preset tunes 153.350 MHz with a 20 kHz bandwidth. Explicit preset buttons still tune their named frequencies; existing plugins keep their behavior.

Verified on Windows with 65 decoder checks, nine host test suites, a known text recording through the actual application, and live message output from a USRP B200 at 153.350 MHz. The specific transmission originally reported as missing was not available for comparison; receive windows without traffic produced no message rows. RF gain was observed rather than optimized by this change.

**Opening Language & country no longer freezes the window while it looks for Chinese, Japanese and Korean fonts.** To list each language by its own name (日本語, 한국어) the window has to know which of those languages this computer can draw, and to find out it read Microsoft YaHei, JhengHei, Yu Gothic and Malgun Gothic from the Windows font folder (14 to 21 MB each) inside one frame, one byte at a time, and then read the ones it used a second time to put them in the text atlas. On a laptop with a slow disk that was a frozen window of many seconds, and the freeze monitor caught it twice in the field: 0.99.70 (signature CE8EBCD986C97CEB, stopped reading a font file) and 0.99.71 (signature D28A155E1A128889, a 13.6 second frame in the frame-start step, 32 plugins fitted and the audio starving). A font file is now read in one call (YaHei, 19.7 MB: 85 to 89 ms before, 11 ms after, on the development desktop with the file already in the system cache), each file is read once, and the search for the first usable font of each of the four scripts runs on a thread of its own, started when the section opens. With every font read made to take 400 ms the call that opens the list returned in 0.1 ms, where the same call took 2.9 s before. The trade is one or two frames of boxes: until the search finishes (39 ms in a run of the real application on this desktop, longer on a slow disk) the native names are drawn as boxes, the rows can already be picked, and a language the computer turns out not to be able to draw is refused afterwards with the same message as before. Two things remain. The thread that draws the window still works out which script each language needs (6 to 8 ms for the 34 listed here). And a user whose Windows language, or the language of the country chosen in this section, is Chinese, Japanese or Korean while the interface is in another language waits for the search once, on the section's first frame, for about the length of four of those file reads, because the two lines that ask whether that language can be drawn ask the exact question (668 ms and 674 ms measured with every read made to take 150 ms; the freeze threshold is 5 s, so it is reached only if a disk takes about a second for each 20 MB file); the previous code read the same four files on the window thread in the next frame, byte by byte and twice over, and those two lines are not yet moved. The search keeps the file it found for each script only until the list's names are in the text atlas: the files it merely looked at (JhengHei and Yu Gothic, 35 MB, because YaHei already draws their names) are then let go, so the memory held after opening the list is what it always was, and choosing Japanese or Traditional Chinese afterwards reads its file once more, in one call.

The host source is committed for development. No FoxSDR 0.99.74 application
release, installer, website deployment or Microsoft Store submission accompanies
the POCSAG plugin-store publication.

## Verification details

POCSAG 1.0.3 or newer can configure reception in FoxSDR 0.99.74 or newer when opened or started without moving away
from a manually tuned paging channel. Its optional preset flags apply the
declared demodulator and bandwidth even when the frequency already matches a
preset, and request flat audio by switching receiver de-emphasis Off. Explicit
preset buttons still tune their named frequencies; other plugins retain their
existing behavior.

An additional opt-in preset flag opens the shared Decoder output window for a
text decoder alongside its own settings panel. POCSAG uses it so the settings
page and received message text are both visible. Plugins without text output
ignore the flag; existing plugins that omit it retain their normal windows.

The plugin ABI remains 3. Synthetic decoder and isolated application checks
establish the software behavior; live reception depends on the signal available
to the radio.

Windows verification used the actual POCSAG 1.0.3 DLL: 65 decoder checks and
nine relevant host test suites passed. Removing the reception setup and
message-window changes reproduced their regression failures; restored builds
passed. A separately generated FM IQ recording displayed `POCSAG TEXT TEST`
in the real application's Decoder output window with the settings page also
visible. Its saved configuration read back 153.350 MHz, NFM, 20 kHz bandwidth
and de-emphasis Off. Tests used isolated application profiles.

One ten-second USRP B200 capture at 153.350 MHz also produced coherent
alphanumeric output at 2400 bit/s when replayed through the final application
and plugin. Another capture produced no message rows. Displayed row counts
include repeated playback and are not counts of distinct transmissions. The
specific transmission reported as missing was not available for comparison.

Direct Soapy/UHD reception on the same B200 also ran successfully with
`SOAPY_SDR_PLUGIN_PATH` both cleared and set. The clear-variable run produced
live message output; the later set-variable run produced no rows during its
receive window. Both used 2 MS/s, TX/RX and a displayed PGA gain of 30 dB,
without stream-error or overflow entries. Different receive windows do not
establish a cause for the difference in message counts. RF gain was observed,
not optimized by this change. These verification runs used isolated profiles;
the saved user profile was not replaced.

The language list's font search is covered by `test_font_scan`, which makes every
font read slow on purpose and checks that each system font file is opened once
(and that choosing Japanese afterwards opens its file a second time, and no other
file, with nothing held in memory beyond the atlas in between),
that asking for the names returns at once while the files are being read, that
the three-way answer (Yes, No, Checking) agrees with the exact one when the search
is done, that the one-call file read returns the bytes a byte-by-byte read does,
that the search finds the faces the on-demand walk finds, and that a search still
running when the program exits is joined rather than terminated. Against the
previous code it failed 9 checks, among them the 2.9 s return and the two reads of
`msyh.ttc` and `malgun.ttf`; with the change it passes, and removing each of the
behaviours it is named after (waiting in `applyPending`, the kept bytes, the
release of the kept files the names did not use, the non-blocking answer, the
exit-time join, the full-length read, the search's first candidate) makes it fail
again. The 350-test suite passed on Windows before the release of the unused kept
files was added; after it, the eight font, i18n and CJK tests were run again and
pass. A run of the
real application with the section open and a Japanese country chosen started the
search, adopted its answer 39 ms later, merged the names' faces on the next frame
and shut down cleanly. Not verified: a slow disk (only a simulated one), and the
Linux build, which only CI compiles.

## Tester features, 2026-10-12

Seven changes asked for on 2026-10-12 (five by testers, the plugin sites and the file-path key by the owner) were built separately, with a fix for the gain readback that the live check of the dials found, and are integrated here on the 0.99.74 development line; none is an application release.

**The top bar now carries GAIN, SQUELCH and VOLUME dials in the order the signal goes through the system, with an AUTO key under the first two: the gain dial sets the radio's first gain stage and its key is the Auto gain switch, and the squelch dial sets the squelch threshold while its key keeps it 8 dB above the measured noise floor - and while the Airband monitor is listening, both act on the monitor's own squelch instead.** The dials are one size, answer a drag or the wheel, and print their setting under them. GAIN reads N/A with no radio and AUTO while automatic gain is on, and is dead in both; its key is dark, with a tooltip saying why, on a radio that has no automatic gain. On the Airband monitor the dial reads and sets its squelch (-110 to 0 dB, the Airband section's own slider) and leaves the receiver's alone, with a line in its tooltip saying so; AUTO there is the section's "Above the noise" rule, 8 dB over the median channel level, re-applied every quarter second. Everywhere else automatic squelch measures the quietest the channel has been over the last ten seconds and re-sets the threshold every quarter second, and it does not count what it reads while the squelch is open, so a carrier does not teach it the floor and close the squelch on itself. A hand on the dial, either squelch slider, the squelch keys, the Above the noise key or the web control puts it back to manual, and it is remembered across restarts (`squelchAuto` in `config.json`, one setting for both squelches).

Making room costs the deck 8% of its size at the window a fresh install opens with: the cluster is 111 units wider, and the SAMPLE RATE and VOLUME meters are kept on the bar by drawing the deck at 0.92 there (full size from a bar of 1313; the enlarged counters at 0.77). The smallest scale falls from 0.62 to 0.57 so the three dials still fit the narrowest window, and the bias tee key keeps a 12-pixel floor. A one-decoder mute banner sits above the meters, not in the middle, at 1600 x 1000. Two geometry faults the new widths exposed are fixed: the mute banner is measured against the meters where they are drawn (scaled with the deck), and the "do the meters fit" rule has the float tolerance its twin always had.

Verified on Windows with a fake radio behind the real window: the application test starts the application once for each scenario and presses and twists the dials through its own input script, aimed from the interface census, 218 checks. The four new parts are on the deck at 1600 x 1000 and 1280 x 720 in the right order and clear of every other part, with both meters still on the bar at 1280 x 720; a press of the gain key switches the radio's automatic gain on and a second press off, a radio without automatic gain is asked for nothing, a half turn of the gain dial from 10 dB asks for 43.3 dB, and a 34-frame hand's turn asks the radio 6 times and ends on 41.6 (41.5 expected). With the receiver running on white noise at -50 and -30 dB the saved squelch threshold is -53.5 and -33.5, 20.0 apart; with the noise at -50 dB for four seconds and then a 30 dB louder carrier held for thirteen it is still -53.6, where a three-second ungated floor gave -23.7. With the Airband monitor listening on two ticked rows, a quarter turn of the dial moves the monitor's squelch from -55 to -18.3 and leaves the receiver's at -100; AUTO puts it at -65 and -44 for noise at -50 and -30 dB (about 20 apart) and the receiver's untouched; the dial, the Airband slider and the Above the noise key each turn AUTO off; stopped, the dial is the receiver's again. The noise-floor tracker has 74 checks of its own, including a 20-second carrier after the floor is learnt, a first estimate formed with the gate open, and a rise under the threshold followed within the window, and each behaviour was removed in turn to see its test go red. The Airband application test (316 checks) passes after the section gained census rects: its runs lasted 4.4 to 4.9 s against 2.0 s of holds, so the display was pacing them. Seven new strings and one more for the Airband tooltip are now translated in all 33 catalogues, so the i18n test passes.

Not verified: no real radio (RTL-SDR, Airspy or B200) was driven by the new dials, only the fake, and automatic squelch and the Airband rule were measured on synthetic noise, not on air. A noise rise past the threshold opens the squelch and holds readings back, so a squelch open for thirty seconds without a break is taken as the floor having risen and is learnt (a safety valve added so the squelch cannot sit open on a noisier antenna for ever); a carrier that holds the channel longer than that, or a continuous broadcast tuned in from a quiet frequency, is still taken for the floor and automatic squelch will close on it.

**The plugin store takes the address of a third-party plugin site: press SITES in the store's top bar, paste the address of someone else's `index.json`, tick the box that says FoxSDR has not reviewed it, and press ADD, and the store lists, installs and updates that site's plugins beside the official ones, each marked THIRD PARTY.** Up to eight sites are kept in the configuration file (`pluginSites`). A site's plugin carries the THIRD PARTY badge on its card and "from <host>" on its page, and always shows the notice box ("This plugin comes from <host>, not from the FoxSDR catalogue. FoxSDR has not reviewed it.", then the maker's own notice if there is one) with the tick that gates the key. Under the top bar each site has a status line: how many plugins it listed, why it could not be read (in amber, the reason word for word), and what it hid - "N hidden: same id as a plugin already listed" (the FoxSDR catalogue always wins an id: a site can never replace, update or retire an official plugin) and "N hidden: files not on the site's own host" (a site's files and pictures must be served from the host of its `index.json`). A site's plugin is known by its site as well as its id, so an official plugin and a site's plugin of the same id can never update, retire or stand in for each other; GET EVERYTHING, UPDATE ALL and the web page leave a site's plugins out; and a site's plugin may not overwrite a file that belongs to another plugin. The loader holds the same line: a module installed from a site never takes a declared name from an official plugin, whatever the versions - the official module runs, and the site's is listed in the Fitted modules window as not loaded with "Not loaded: it declares the same name as the official plugin ..." (before this, the higher version won, so a site's module declaring an official plugin's name with a higher version switched the official one off). Every download still goes through the same gate as any plugin: https only, the exact ABI, the sha256 the site published, the byte cap, no redirect to another host. REMOVE forgets a site and deletes its kept copy; what was installed from it stays installed, the Fitted modules window says it came from a site that was removed, and it gets no more updates. `docs/THIRD-PARTY-SITES.md` tells a plugin author how to host a site, including the same-host rule and the declared-name rule.

**Switching automatic gain off now gives the radio its manual gains back and reads them again, so the Source section's sliders and the GAIN dial show what the radio really holds.** The live check of the dials on the B200 found it, and it was already there before them: after the Auto gain switch was turned off the radio fell about 35 dB (the in-channel level went from -40.7 to -75.4 dBFS) while the readback and the dial still said 76.0 dB, and setting 76.0 again put it right. The window read the gains back after the switch for an Airspy only. Now every radio that accepts the switch is handled in `changeAutoGain`, which the Auto gain box, the AUTO key and the web control all use. Switching ON keeps the numbers the user had set and reads every stage back, so the dial shows what the radio reports while it gains itself. Switching OFF gives every stage its kept value again (for a radio that was opened already on automatic gain, the value the open read), drops without a word a step the radio turns down, as the dial's own steps are, reads every stage back, and writes one diagnostic line, `source: manual gain restored after auto gain off`. A switch that changes nothing leaves the gains alone, and the box still shows what the radio accepted rather than what its `autoGain()` says, as it always has for a radio that is not an Airspy.

**A plugin can now send transmit audio through FoxSDR, only to a radio you have opened, only if you granted that module TRANSMIT and armed the TRANSMIT page for it, and never for longer than the latch's 60 seconds.** The new capability `CASCADE_CAP_TX_AUDIO` (host API level 2) hands the host 48 kHz mono audio through a `pull()` function, the way `CASCADE_CAP_AUDIO_OUT` hands audio the other way. A module that wants to transmit shows "Can transmit through FoxSDR" in the plugin store and on its plate. Once it has asked, its page in Fitted modules offers **GRANT TRANSMIT** (per module, off by default, saved by file name like the other two grants), and the TRANSMIT page gains **ARM FOR PLUGINS** with **5 MIN**, **15 MIN**, **60 MIN** and **OFF** keys, a countdown that names the module, and a **DATA (flat)** tick that sends plugin audio as NFM with pre-emphasis off. The module chooses nothing else: the frequency, the power and the mode stay the ones on the page.

The key is open only while the grant, the armed window, a live TRANSMIT page, a fresh frame tick and the module's own `active()` are all true together. A hand on PTT or the latch always takes the transmitter first, and the web control and rigctld still cannot key it. The window is never saved: nothing in `config.json` can arm anything, and starting FoxSDR again always starts disarmed. The window closes, not merely pauses, when it times out, when you press OFF, when the page is closed or rolled up, when the radio is closed or faults, when the grant is withdrawn, when the program stops responding, when a configuration is loaded, and when the 60 second cap fires. Only one module holds the transmitter at a time (the first granted module in load order, for the length of a transmission); a second one waits and its plate says so. Audio that is not a number is replaced by silence and anything past full scale is clamped, a negative `pull()` result stops that module's transmit audio, and the diagnostic log records `tx: armed <n> min`, `tx: plugin <name> keyed`, `tx: plugin <name> unkeyed (<reason>)` and `tx: disarmed (<reason>)`, never a frequency. The rule in `docs/TRANSMITTING.md` and in the transmitter's header that said only a hand could key it now says a hand, or a plugin you have granted and armed.
