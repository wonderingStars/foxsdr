# Screen hand-off for the next screen lane ("screen lane L"): every control the engine can answer today and no screen draws

Written by engine merge 3 (2026-11-12/13) on `engine/multi-radio`. Sources: the SCREEN HAND-OFF sections of `wire-a.md` (section 7), `wire-b.md` (4.2, 4.2a), `wire-c.md` (section 4 of the lane's final record, which the lane has not yet committed: its text is `D:/foxsdr-build/prep/lane-results/wire-c-final-record-pending.md`), `radio-bridges.md` (REGISTRATION HAND-OFF and NEEDED LIBRARIES), section 8 of `engine-merge-2.md`, and the rows `screen-k.md` says it did not build.
Every label is English and untranslated; every control is OFF until the user acts. Operation numbers are in `src/core/app_commands.hpp` (`FOXAPP_OP_*`), text parameters are JSON unless the row says otherwise; a per-radio operation addresses the radio by the command's target. Facts are read with `get_setting("fact.<key>")` by a LOCAL session (a REMOTE session is denied every operation here). Status of every operation: engine side built and tested, no Slint control, no string, no drive script.

How to read the last column and the DUPLICATE marks: `wire-a`, `wire-b`, `wire-c`, `bridges` (radio-bridges), `K` (screen lane K: not built), `merge-2` (engine-merge-2 section 8). A row marked DUPLICATE is offered by two lanes; the "keep" sentence says which one the screen should use. Where screen lane K or J already drew a control (rows 4900-4914 and 5200-5236 of `docs/slint-port-tick.md`), the engine operation that does the same job is marked DUPLICATE and the screen's own is kept, unless the row says otherwise.

## C. Needed libraries (ONE table, engine fixes 4; `engine-fixes-4.md` item 4 says how the two shapes of merge 3 became one)

ONE row type, `cascade::source::needed::Info` (`src/source/needed_library.hpp`), and ONE table of nine rows (`needed::neededTable()`): wire-b's eight and the SDR-IQ's `ftdi-d2xx`. Library ids are stable. A row carries a kind (`library-file`, `soapy-module`, `running-program`, `remote-software`, `user-file`), the SELECT_SOURCE key it serves (`source_kind`, empty for a Soapy module), the file names looked for, the steps, the licence line, `page_status` ("verified" only when the address was read in the publisher's own documentation; an address that is not verified is shown to nobody) and `fetch_allowed` ("no (unverified)" today for every row), and its own check function. The operation and the fact report all nine; there is no second shape and no second operation.

"Check again" answers one of SEVEN states: `working`, `not-found`, `too-old`, `wrong-32-bit`, `would-not-load`, `not-a-library` (the six of the owner's rule, names and meaning unchanged) and `cannot-check` (a running program, software on another machine or a firmware file: nothing on this PC to look at; opening the radio says whether it works). What a check does depends on the row: it NEVER loads vendor code except for `ftdi-d2xx` (the SDR-IQ bridge's own silent load check, which loads the library, checks its eight calls and unloads it: depth `loaded`); every other file row reads the file's headers only (depth `headers`), so for those rows `working` means "found, 64-bit, well formed; it is loaded only when the radio is opened", the sentence says so, and `too-old` and `would-not-load` cannot be answered for them. Nothing is downloaded, opened as a web page, copied or written by a check, and no Windows dialog can be raised by it.
