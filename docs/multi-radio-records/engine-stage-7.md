## B1. Source kinds for radios 2 to 8

What was wrong: `RADIO_ADD` accepted `file:`, `open-pluto:` and `open-rtltcp:` but a file never played (the I/Q file's open result is collected by `pollIqOpen`, which only radio 1's pass called, and there was ONE open worker for the engine), and none of the three was saved with its kind. The Pluto and rtl_tcp opens themselves (the first radio's worker open, `launchDeviceOpen`) already worked for any radio: the record of stages 5 and 6 was wrong that a Pluto "cannot be opened as a second radio" through `RADIO_ADD`; what was missing was save, restore and the transmitter's path.

Built:
* **A file open worker per radio** (`EngineDiskWork::iqOpenFor(slot)`), collected under that radio's scope in `pumpExtraReceivers` (`pollIqOpen`); a result for a radio removed while it opened is collected and closed off the pass (`pollDiskJobs`; one more one-shot thread site, listed in the thread inventory). Two radios opening files in the same pass each get their own.
* **`noteAsyncOpenEnded`**: a radio added on a file, a Pluto or an rtl_tcp server whose open fails says why in `fact.radio.<n>.refusal` (nothing said anything before).
* **Saved with the real kind**: `SavedRadio.sourceKind` may be `file` (args = the path), `pluto` (`uri=...`), `rtltcp` (`rtltcp=host:port`). Restore: a file by `restoreExtraRadioFile` (the first radio's start-up open of a file), the others by the ordinary device open. A source that is not there (missing file, unreachable server, Pluto that does not answer) follows the existing rule: the generator, named in `fact.radio.restore` and `fact.radio.<n>.refusal`, and the next save still names the real source (`restoreKeep_`). A missing saved file counts the existing `Recovered::IqFileGone` word (a second site; no new word).
* **The rtl_tcp ledger key is `rtltcp=<address>` whichever spelling was typed**, so the same server twice is refused with the holder named (it was keyed by the bare spelling and could be opened twice).
* **The transmitter's address is seeded from a Pluto that is another radio's** (`transmitArgsSeed`), so `transmitRadioFor` has a real path to radio 2, also after a restart.
* The sound card, `row:soundcard` and `row:iqfile` stay `UNSUPPORTED`.
* New fact `fact.radio.<n>.source` (the source kind).

## `fact.radio.<n>.range` (orchestrator's addition)

What the source layer exposes: `DeviceSource::frequencyRangeHz(lo, hi)` (SoapySDR's overall range read at open, the RTL-SDR tuner's range, a Pluto's published LO range, the rtl_tcp tuner's range); it answers false when the device reports none. The fact is `"<lowest>,<highest>"` in Hz, asked once the device is open and kept in the `Receiver` (hashed by the lists fingerprint so it appears when it becomes known). Absent for the generator and for an I/Q file (a file's centre is nominal and takes any value; the tuner allows no range of its own). Tested: the rtl_tcp radio (lo > 0, hi > lo), the fake Pluto's published range exactly ("70000000,6000000000"), the generator and the file absent; break-it: the fact never written: 4 failed. Documented in API.md 6.20 and additions 9.23. (The break-it also showed a trap of this lane's own: the mutation helper restores a file with `git checkout`, which put back the committed copy of a file that held uncommitted work; the work was redone and committed before the second break-it.)
