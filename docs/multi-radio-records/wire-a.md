Conventions I will use (stated once; the rows say only what differs):
* One NEW engine file per feature group, `src/engine/engine_wire_a_<group>.cpp` (as `engine_recname.cpp` does), plus pure helpers in `src/core/wire_a_*.{hpp,cpp}`; members are appended to the END of `engine.hpp` inside `// wire-a begin` / `// wire-a end`.
* Persistence: one small JSON/text file per feature in the per-user folder beside `config.json` (`scan-plan.json`, `bookmark_notes.json`, `band_memory.json`, ...), the way `record-name.txt` and `macros.json` are kept. `AppConfig` and `config.json` are NOT touched (the default file stays byte-identical and loadable by the previous version), except row 41 (an existing key, a new value).
* Every new op: `#define` + `kOps` row appended, a case appended in the `engine.cpp` apply switch that only forwards to a function in my new file, a fact `fact.<area>.*` where a screen needs to read it back. Anything that opens a file, a port or a device is OFF by default.
* Test file per group `tests/test_engine_api_wire_a_<group>.cpp` (globbed; drives the op through the engine, failure path, one break-it for the important rows).
