## Features and fixes, 2026-10-12

Two changes were made on 2026-10-12, after 0.99.74 was published: the list of aircraft heard without a position, and the remembered manual gain. The section after them, on receiving ADS-B on a B200, is a note and not a change.

**The target list now lists the aircraft the receiver has heard but cannot place yet, below the placed ones and counted apart, and never draws them.** An ADS-B decoder hears an aircraft's identity, altitude or callsign before its position message arrives, and until now it had to hide the aircraft until it could place it. The plugin ABI gains two definitions, and the plugin repository's copy of `plugin_abi.h` must receive the same two lines: `CASCADE_TRACK_FLAG_NO_POSITION` (`0x00000004u`, in `CascadeTrack::flags`: the coordinates are NaN, the source hears this target and cannot place it yet, a host lists it and must not draw it) and `CASCADE_STATE_LISTS_UNPLACED_TRACKS` (`0x00008000u`, the next free `CASCADE_STATE_*` bit after `_TRANSMITTING` at `0x4000`: the host understands the flag, and a plugin may publish such tracks only when it sees this bit). The host sets the bit in every `CascadeReceiverState` it fills, for every plugin, with no grant behind it. The ABI is still 3 and the host API level is unchanged. A track that carries the flag, or whose latitude or longitude is not finite (so an old or careless plugin that sends NaN without the flag is covered too), is kept in a list of its own (`PluginUi::unplacedTracks()`), out of the vector the map, the scope, the coverage map, the auto-fit, the follow, the web snapshot and the patch map's map part are all fed from, so none of them can draw it, fit to it, follow it, count it in the coverage map or call it "on screen"; the map also checks the position itself, and `MapView::goTo` refuses a place that is not a number. Its trail is dropped too (a path whose id is a no-position track's), and no altitude is recorded for it. In the target list it is a row after the placed rows, dimmed (drawn at 60% of the strength a placed row of the same age has), with its label and id, a second line with the altitude where it is known (`35000 ft - no position yet`; kilometres for a satellite) or just `no position yet`, a hover that shows the detail block (whose position line says `no position yet` and which has no range or bearing), and a Details button; it fades and drops on the same `ageMs` rule as a placed target of its kind. The heading reads `12 targets, 3 heard without a position` when the second number is not zero (and `1 target, 1 heard ...` and `3 of 41 targets, 2 heard ...` in the singular and the On-screen-only forms), and the three plain lines are exactly as before when it is zero; the rail chip keeps counting the placed targets. With **On screen only** ticked the heard rows are gone, because they have no place on the map and so are never on screen, and the heading still counts them. The details window and the rail's Target details section find such a target by id, and the registry lookup works for it as for any other; their Go to on map and Follow keys are dead for it until it has a position.

One behaviour changed that is not new surface: a track with a latitude or longitude that is NaN and no flag used to be dropped without a word, and is now listed as heard without a position; one with finite coordinates outside the globe (91 degrees, 999 degrees) is still dropped. The existing test that named the old behaviour was changed to say so.

**A radio's manual gain is now remembered and put back at its next open, so a B200 set to 76 dB no longer starts at 30 dB.** Every open of a SoapySDR radio pushed a mid-dial 30 dB into every stage (the B200 here has been opened that way for months) and nothing remembered what the hand had set, so the owner's B200, run at 76 dB, began each session 46 dB down. `AppConfig::manualGainByRadio` (`"manualGainByRadio": { "<radio key>": { "<stage>": dB, ... } }` in `config.json`) keeps, under the same radio key as the bias tee and the auto gain switch, each stage the user has set and what the radio read back for it (the radio quantises). It is written when the user changes a stage and the radio accepts it - the Source section's sliders, the top bar's GAIN dial, the scope face's GAIN knob and a browser's gain control - and never by the open's own 30 dB push, by the restore itself, by a step the radio refuses, or while automatic gain is on. At an ordinary open (not the reopen after a driver fault, which restores the gains the user had a moment ago, and not an Airspy, whose gains are part of its gain mode) each remembered stage the radio still lists is set again after the push and the first readback and before the remembered auto gain is put back, clamped into the stage's own range, the mirror is read back so the dial and the sliders show what the radio took, and one line is logged: `source: manual gain restored - PGA 76.0, ...`. A stage the radio no longer lists is ignored and kept for a radio that has it; a stage the radio turns down is skipped without a word. The file is read element by element: a radio whose value is not an object or whose key is not `<kind>|<args>`, a stage with no name or whose value is not a finite number, and a radio left with no stage are skipped, at most 64 radios and 16 stages of each are kept (the first sixteen by name), and a stage that is not a finite number is not written. The save debounce sees a change (`configsEqual`), and the start-up state keeps it. `docs/MANUAL.md` and `docs/DIAGNOSTICS.md` say so.

## Receiving ADS-B on a B200

**On a B200, set the antenna port to the one the antenna is on, run the gain well below the top, and put a 1090 MHz band-pass filter in front of the radio.** These are measurements from one B200, not rules that FoxSDR enforces. The antenna port must be the one the antenna is plugged into: TX/RX against RX2 was 58 decoded lines against 2 for the same aircraft. At 60 to 65 dB the radio decoded four to eight times as many frames as at 76 dB on this front end. An unfiltered B200 is compressed by strong signals between 700 and 900 MHz, so a 1090 MHz band-pass filter helps.

ADS-B plugin 1.9.0 places an aircraft from a single frame once the aircraft is known, and from one frame against the receiver position for an aircraft below about 32,000 ft within 100 nm.
