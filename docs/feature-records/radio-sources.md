## Part 1: R13 SDRplay low-IF choice, W4a diagnostic report model, W4c service restart over an injected SCM

Files: `src/source/sdrplay_if_mode.{hpp,cpp}`, `sdrplay_diag_report.{hpp,cpp}`, `sdrplay_scm_restart.{hpp,cpp}`, test `tests/test_sdrplay_ifmode_diag.cpp`.

**What existed (verified in this tree).** `sdrPlayRatePlan()` (sdrplay_source.cpp) is zero-IF only since 0.99.44: two RSP2 field logs showed a low-IF 6 MHz plan delivering 6 MS/s where 2 MS/s was expected (the log lines are quoted there). The SDRplay probe (sdrplay_probe.cpp, stepIfModes) already holds the low-IF combinations transcribed from the API specification section 3.15. The tree also already has an elevated cmd.exe service restart (`SdrPlayServiceRestart`) and a probe report; W4a and W4c here are the two things asked for that it does not have: a plain report model + formatter, and a direct SCM restart with an injected interface.

**What was built.**
* `SdrPlayIfMode {ZeroIf, LowIf}`, `sdrPlayRatePlanForMode(rate, mode, plan)`: ZeroIf forwards to `sdrPlayRatePlan` unchanged (the default; `sdrplay_source.cpp` is untouched). LowIf offers 62.5k, 125k, 250k (fs 2 MHz, IF 450, BW 0.2), 500k, 1M, 2M (fs 2 MHz, IF 450, BW 0.6), 3M (fs 6 MHz, IF 1620, BW 1.536), 4M (fs 8 MHz, IF 2048, BW 1.536), 8M (fs 8 MHz, IF 2048, BW 5.0); every other rate is refused, never guessed. Output = fs / decimation.
* `sdrPlayLowIfRateVerdict(plan, measuredHz)`: classifies a measured stream rate as AsPlanned, DeliversAdcRate (the 0.99.43 field behaviour: within 2% of fsHz while decM != 1) or Other. The wiring lane must run it on the first real low-IF stream and refuse low-IF on a mismatch.
* `SdrPlayDiagReport` + `formatSdrPlayDiagReport`: API version/path, service summary, device list (model from hwVer, serial masked to the last four characters, tuner, RSPduo mode, in-use flag), last error and step.
* `restartSdrPlayServiceVia(ScmInterface&, name, limits)`: query, stop if not stopped, wait for Stopped, start, wait for Running; results Restarted, AccessDenied (Windows error 5, sentence says administrator rights), NotInstalled (1060), StopTimedOut, StartTimedOut, OtherError(number). `WindowsScm` wraps OpenSCManagerW / OpenServiceW / ControlService / StartServiceW / QueryServiceStatusEx (CONNECT, QUERY_STATUS, START, STOP rights only). `restartSdrPlayServiceNow()` is called by nothing and by no test.

**UNPROVEN / not verified.** The SDRplay API specification PDF was not reachable in this lane: the low-IF combination table is the project's earlier transcription, not re-read. Whether low-IF takes effect on a real RSP, and what rate it delivers, is unproven (no RSP). The real SCM wrapper compiled but was never run; the service was never touched.

## Part 2: R4 SoapyRemote client (shared network-source base)

Files: `src/source/net_sample_source.{hpp,cpp}` (the base class every network source of this lane shares, plus `UdpTransport`), `soapy_remote_protocol.hpp` (codec), `soapy_remote_source.{hpp,cpp}`, tests `tests/test_soapy_remote_source.cpp`, `tests/src_test_net.hpp` (loopback helpers shared by the three network tests), thread-inventory row `src/source/net_sample_source.cpp` (R_DRIVER, one reader thread) in `tests/thread_inventory_rows.inc`.

**Documents.** https://github.com/pothosware/SoapyRemote: `LICENSE_1_0.txt` opened first (first line "Boost Software License - Version 1.0 - August 17th, 2003"; README: "Use, modification and distribution is subject to the Boost Software License, Version 1.0"; every source file carries `SPDX-License-Identifier: BSL-1.0`), so the sources were read (raw text fetched to a scratch folder outside the repository, read only, nothing built or linked): `common/SoapyRemoteDefs.hpp` (numbers), `SoapyRPCPacker.{hpp,cpp}`, `SoapyRPCUnpacker.{hpp,cpp}` (message layout), `SoapyStreamEndpoint.{hpp,cpp}` (datagram header, ACK), `client/Settings.cpp`, `Streaming.cpp`, `Registration.cpp`, `ClientStreamData.cpp` (call order, arguments, sample conversion). Master at 2026-11-11, RPC version word 0x000400. The format is written out in the header of `soapy_remote_protocol.hpp`.

**What was built.** Connect by address (default port 55132, TCP control), MAKE with the user's device args plus the `soapy_remote_no_deeper` key, native stream format and full scale, rates, frequency range, antennas, gains and gain ranges, gain-mode and frequency-correction flags; RX stream on channel 0 over `tcp` (DEFAULT: deliberate, a udp stream needs the server to reach this machine) or `udp`; flow-control ACKs; CS8, CU8, CS16 and CF32 to complex float; setFrequency, setSampleRate (snapped to an offered rate), setGain (clamped to the range), gain mode, antenna, correction; ACTIVATE/DEACTIVATE on start/stop; CLOSE_STREAM, UNMAKE, HANGUP on close. Discovery is left out. CS12, multi-channel streams, log forwarding, hardware time and TX are not built.

**Design points worth knowing.** The stream sockets are read in 200 ms slices and a TCP datagram is reassembled across slices (a header split by a pause loses nothing: `testSplitHeader`), because `shutdown()` alone did not wake a parked receive in this test against a server that keeps its end open (the first run abandoned a reader for 2.5 s; found by the silent-server close test). A streaming source whose server goes silent for `max(3, timeout/200 ms)` slices latches a fault ("the radio server stopped sending"); an idle (not activated) source tolerates silence. Stream status datagrams TIMEOUT/CORRUPTION/OVERFLOW/UNDERFLOW (-1/-3/-4/-7) are counted as dropped, any other negative code is fatal. The sample conversion follows the reference client's: CU8 is `(u - 127) / scale`, the others `v / scale` (scale = the server's reported full scale).

**UNPROVEN.** Against a real SoapySDRServer: everything on the wire. The stand-in (`tests/test_soapy_remote_source.cpp`) has its own packer and parser with literal numbers, written from the same reading, so it cannot show the reading was right; it did catch two slips of mine in the first run (the call number is a typed INT32; every STRING has its own type byte). Not read, so not built: the CS12 format, the server's exact behaviour on a client FIN, what a real server does when ACKs stop. UDP stream defaults were never used on a real network; the `window`/`mtu` the client announces (1 MiB / 1500, so 699 datagrams in flight) is a choice, not the reference client's 42 MiB.
