## Part 1: Linux in-app updater (U5)
Built: `core/linux_update.{hpp,cpp}` (decisions and the apply steps, behind an `UpdateHost` interface of file and process operations), `core/linux_update_host.{hpp,cpp}` (`FsUpdateHost`: the std::filesystem half, portable and run on Windows; `SystemHost`: POSIX half, non-Windows only), `core/linux_update_fetch.hpp` (ranged download template over the cpp-httplib client).

Decisions (`decide`): channel (stable/beta; a mismatched answer is refused), numeric version order (pre-release older than its release), downgrade refused, withdrawn list, asset chosen by architecture and install kind (AppImage file or unpacked tarball tree), and TELL-ONLY (never replace) for a package-manager install, Flatpak, Snap, container, unknown install, or a folder the user cannot write.
Apply (`applyUpdate`): writable and free-space checks, exclusive lock file, resumable download (partial named after the asset digest; larger than the asset: discarded; a resumed file that fails its hash: ONE clean retry from zero; second failure: refused), sha256 check (mismatch deletes the bytes and installs nothing), payload checks (ELF magic; tar listing with no absolute path, `..`, backslash, or second top-level entry), `target -> target.old` then `staged -> target` (second rename failure restores), a pending marker, a start-once smoke run `--version` of the new copy (must exit 0 and print the version; an AppImage is also tried with `--appimage-extract-and-run` for machines without FUSE), restore of the old copy when it does not run. `confirmStartup` (call early in every start) deletes the `.old` copy after the new one has started for real, undoes an interrupted swap, and drops a stale marker.
Manifest: reads an optional `linux` object of the same `/api/update` answer (`version`, `channel`, `withdrawn`, `assets[{kind,arch,url,sha256,size}]`); every safety field is refused rather than warned about (https, host foxsdr.com or a subdomain, 64-hex digest, structural version parse, 1 GiB cap, at most 16 assets; a bad asset is dropped alone). THE SERVER DOES NOT EMIT THIS OBJECT YET (hand-off below). Request URL: `updateRequestUrl` adds `platform=linux&arch=`.

Proven on Windows (`test_linux_update`, 208 checks): in-memory fake host (every branch and refusal), the real `FsUpdateHost` on a temp directory (real renames, real rollback, exclusive lock), a stand-in `httplib::Server` on 127.0.0.1 (resume sends `Range: bytes=N-` and appends; a server that ignores Range restarts the file; a Content-Range that does not start where asked is refused; 416 deletes the partial; 404 and 302 fail and no redirect is followed; byte cap; cancel; a dead port) and an end-to-end `applyUpdate` over that socket; a 4000-case mutation fuzz of the manifest and archive-listing parsers.
UNPROVEN ON LINUX: `SystemHost` (https download with `httplib::SSLClient` and strict certificate checking, `tar -tzf` / `tar -xzf --no-same-owner` through fork/exec, program run with a timeout and SIGKILL of its own child, `probeThisInstall` reading `/proc/self/exe`, `$APPIMAGE`, `/.flatpak-info`, `/.dockerenv`, `dpkg -S` / `rpm -qf`); atomicity of `rename(2)` for a directory swap; a running AppImage being replaced under itself; whether `<app> --version` works inside a FUSE-less AppImage; symlink entries inside a tarball (only names are checked; tar's own defaults and a digest-verified archive are the second line).
Documentation used: https://docs.appimage.org/packaging-guide/environment-variables.html (`APPIMAGE` = absolute path of the AppImage file, symlinks resolved), https://docs.appimage.org/user-guide/troubleshooting/fuse.html (`--appimage-extract-and-run`; that arguments after it reach the program is NOT stated on the page), the existing `tools/check-linux-tarball.sh` and `build.yml` (tarball layout, `--version` prints `FoxSDR <version>`).

## Part 2: udev rules from the app (W14)
Built: `core/udev_rules.{hpp,cpp}`. `supportedRadioIds()` collects (vid,pid) from `rtlSdrUsbIds()`, the HackRF/RX888/Airspy/Airspy HF+/HydraSDR/AOR protocol constants and `msi2500::deviceModels()`; `generateRulesText()` writes the rules from it; the committed `installer/linux/99-foxsdr-sdr.rules` was checked to name exactly the same radios (test). The install path: `pkexec /usr/libexec/foxsdr/foxsdr-udev-helper` with NO arguments. The helper (`packaging/linux/foxsdr-udev-helper`, generated by `generateHelperScript`, a test keeps the committed copy equal) refuses any argument, reads no input, bakes in the rules text (which must pass `validateRulesText`: only exact FoxSDR rule lines and ASCII comments), writes `/etc/udev/rules.d/99-foxsdr-sdr.rules` through a temp file and `mv`, then `udevadm control --reload-rules` and `udevadm trigger --subsystem-match=usb --action=add`. Before running it the app reads the helper from disk and refuses it unless it equals what this version generates. The user is shown `Plan::rulesPath` and `Plan::rulesText` and must agree (`installRules(host, userAgreed)`; false runs nothing). pkexec exit 126 = dialog dismissed, 127 = not authorised or no agent (verified from https://www.freedesktop.org/software/polkit/docs/latest/pkexec.1.html, which also gives the `org.freedesktop.policykit.exec.path` annotation used in `packaging/linux/com.foxsdr.install-udev-rules.policy`).
Proven on Windows (`test_udev_rules`, 133 checks): table contents, ordering/uniqueness, equality with the shipped rules file, the validator against 14 hostile lines, helper text properties (no `$1`/`$@`/`read`/`eval`/`sh -c`, quoted here-doc, refuses to bake invalid text), refusals through the fake host: no pkexec, no helper, tampered / foreign-version helper, user declines, exit 126, 127, -1, 1, 2, "success" with a missing or wrong file, already installed. The helper script was also checked with `sh -n` and run once in Git Bash against a temp directory with a stub `udevadm` (it wrote the file byte-identical to the baked rules, called reload then trigger, left no temp file, exit 2 when given an argument): evidence for the script's logic, NOT for Linux.
UNPROVEN ON LINUX: a real polkit prompt, real udevadm, the policy file being accepted by polkit, `/usr/libexec/foxsdr` existing on every distribution, `dpkg -S`-style ownership. The helper must be root-owned at its fixed path (a package guarantees this; the interface cannot check ownership).
