# FoxSDR links Worker

Keeps the web addresses of the libraries FoxSDR users may have to install **alive and updatable**. A plugin or radio setup page that needs a library the user installs names it by id; the address behind its "Open the download page" button comes from this registry, so it can change without a new FoxSDR release, and a daily check notices when an address dies or starts redirecting somewhere it should not.

**Status: built and tested locally, NOT deployed.** No Cloudflare resource exists for it. Read DEPLOY.md for the owner decisions and the exact steps.

## The routes

| Route | Answer |
|---|---|
| `GET /v1/libraries.json` | the registry, byte for byte (`ETag`, `Cache-Control: public, max-age=3600`, `X-FoxSDR-Schema: 1`) |
| `GET /v1/libraries.signed.json` | the same bytes in the owner's Ed25519 signature envelope (404 until signed) |
| `GET /v1/status.json` | per id: the combined status and the last check time, nothing else |
| `GET /v1/go/<id>` | 302 to the official page while the link is healthy; otherwise a plain "this link is being updated" page (503) |
| `GET /health` | `{"ok":true,...}`, no storage touched |
| `GET /admin/links.json` | every row that is not fine; `Authorization: Bearer <ADMIN_TOKEN>`; 401 / 503 otherwise |
| cron `17 4 * * *` | the daily checker |

No cookies, no query parameter is read, nothing about the visitor is logged or kept; the registry request carries no install id. Unknown ids and other paths are 404.

## The checker

For each row with an address: `HEAD` (one ranged `GET` of byte 0 when a server refuses HEAD), 8 s timeout, `User-Agent: FoxSDR-link-check`, each address once per run. Redirects are followed **by hand**: a redirect to a host that is not in the row's `allowed_hosts` is recorded as **moved** and that host is never requested. **Three failed runs in a row make a row `broken`.** A changed size or ETag on a download with a pinned checksum is flagged `changed`. The checker **never edits an address**; its findings are an overlay and the status anyone sees is the worse of the registry's and the overlay's. The last 30 results per id are kept in one KV key. A new address deployed for a row starts clean.

## Layout

```
registry/libraries.json        the single source of truth (edit this, nothing else)
registry/schema.json           the shape, documented (src/validate.js is the authority)
registry/libraries.signed.json created by the owner's signing step; absent until then
src/validate.js                registry rules            (pure)
src/probe.js                   one address, redirects    (pure apart from the fetch it is given)
src/decide.js                  statuses, three strikes, moved host, changed, reports   (pure)
src/check-run.js               one daily run             (pure apart from fetch and state)
src/worker.js                  routes and the cron handler
src/registry-bundle.js         GENERATED by tools/build-bundle.mjs; a test keeps it current
tools/                         validate, build-bundle, predeploy, sign-registry (dormant), envelope
test/                          node --test, no dependencies
wrangler.toml                  follows telemetry-worker/wrangler.toml
```

## Run the tests (no install, no network)

```bash
cd links-worker
node --test "test/*.test.mjs"
```

Needs Node 22.7 or later (the same as the telemetry Worker's tests).
