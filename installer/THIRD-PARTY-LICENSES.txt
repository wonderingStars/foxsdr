COMPONENT: SDRplay API (interface description written from the public header;
           the library is the user's own install - nothing linked or shipped)
======================================================================
======================================================================
FoxSDR's SDRplay driver (src/source/sdrplay_api_decl.hpp and
src/source/sdrplay_source.*) drives an RSP through sdrplay_api.dll from the
SDRplay API 3.x package THE USER INSTALLED. That library is loaded at run
time by name from SDRplay's documented install path, its entry points are
resolved with GetProcAddress, and it is called directly. No part of the
SDRplay API is linked into this product, no SDRplay binary or header is
distributed with it, and nothing of SDRplay's is present in this
repository. An RSP cannot be reached any other way: SDRplay publish no
device protocol and the tuner is programmed by a Windows service that owns
the USB handle.

src/source/sdrplay_api_decl.hpp is an INTERFACE DESCRIPTION - our own
declarations, in our own names and our own file, of the structures, enums
and function signatures the driver uses - written from SDRplay's publicly
published sdrplay_api headers so that this product can call a library it
does not ship. Each structure carries a static_assert on its size, alignment
and member offsets, checked against the vendor headers for API 3.07, 3.11
and 3.15 compiled with this product's own compiler, so that a layout change
fails the build rather than corrupting the service's memory in the field.

The CALL SEQUENCE - the order in which Open, ApiVersion, LockDeviceApi,
GetDevices, SelectDevice, GetDeviceParams, Init, Update, Uninit,
ReleaseDevice and Close are used, which update reasons accompany which
parameter change, how the sample rate below 2 MS/s is produced by
decimating a low-IF or zero-IF front end, and the per-model antenna, notch,
bias-tee and LNA-state tables - was learned from SoapySDRPlay3, which is
MIT licensed. No SoapySDRPlay3 code is present in this product.

THE NATIVE RTL-SDR DRIVER IS AN INDEPENDENT IMPLEMENTATION.

FoxSDR can open an RTL2832U dongle directly, without SoapySDR and
without libusb, through its own driver (src/source/rtl2832u.*,
src/source/tuner_r82xx.*, src/source/rtlsdr_source.*) over its own
WinUSB transport (src/usb/). That code is original to this product and
is licensed with it.

librtlsdr, and the RTL-SDR Blog fork of it, are GPL-2.0. NO CODE,
COMMENT, STRUCTURE OR IDENTIFIER FROM EITHER WAS COPIED, and neither is
linked into this product in any form - not statically, not dynamically,
and not as a runtime module loaded by this driver.

What those projects WERE used for is documentation. The RTL2832U and
the Rafael Micro R820T/R828D have no publicly published register map,
so the only available description of how the silicon behaves - which
vendor request reaches which block, what the demodulator's
initialisation values are, how the resampler ratio and the tuner's
fractional-N PLL are computed, which tracking-filter band applies at
which frequency, and what each gain step was measured to be worth - is
the behaviour of the drivers that already speak to it. Those are facts
about hardware, and facts are not copyrightable. This implementation
was written from them in this codebase's own style, with its own
structure and its own comments explaining why each step exists, and is
verified against the hardware rather than against the reference: see
tests/test_rtlsdr_source.cpp, which asserts the byte sequences this
driver puts on the wire, and tests/test_rtlsdr_live.cpp, which measures
a real dongle.

The same applies to the RTL-SDR Blog V4's upconverter, notch filters
and input switching, which were described from the behaviour of that
fork and implemented independently here.

THE NATIVE MIRICS DRIVER IS AN INDEPENDENT IMPLEMENTATION.

FoxSDR can open a Mirics MSi2500 + MSi001 receiver directly, without
SoapySDR and without libusb, through its own driver
(src/source/msi2500.*, src/source/tuner_msi001.*,
src/source/mirisdr_source.*) over its own WinUSB transport (src/usb/).
That code is original to this product and is licensed with it.

libmirisdr, and the libmirisdr-4 fork of it, are GPL-2.0. NO CODE,
COMMENT, STRUCTURE OR IDENTIFIER FROM EITHER WAS COPIED, and neither is
linked into this product in any form - not statically, not dynamically,
and not as a runtime module loaded by this driver.

What those projects WERE used for is documentation. The Mirics MSi2500
bridge and the MSi001 tuner have no publicly published register map, so
the only available description of how the silicon behaves - which vendor
request reaches which block, how a register write is encoded into a
control transfer with no data stage, what the ADC's initialisation values
are, how the sample clock's divider and fraction are computed, which
band, local-oscillator divider and input-switch word apply at which
frequency, how the tuner's fractional-N synthesiser and its correction
trim are programmed, and what each gain stage is worth in decibels - is
the behaviour of the drivers that already speak to it. Those are facts
about hardware, and facts are not copyrightable. This implementation was
written from them in this codebase's own style, with its own structure
and its own comments explaining why each step exists, and is verified
against arithmetic the reference itself produces rather than against its
source: see tests/test_mirisdr_source.cpp, which asserts the byte
sequences this driver puts on the wire against values computed by the
reference's own formulae.

One thing that description did NOT cover is recorded in
src/source/msi2500.hpp: the files that unpack the bit-packed sample
formats were not among those read, so the twelve- and ten-bit packings
are derived from the reference's own size arithmetic and are marked as
such in the source and in the tests.
